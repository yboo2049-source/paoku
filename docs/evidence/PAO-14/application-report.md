# 应用、交易和存档实现

应用职责只写 `src/application/`、三个指定新单测文件和本报告/日志。已读实施计划和架构规范；具体接口遵从 PAO-9 §4–6 和派发白名单。无 DOM、物理、生成、渲染和音频算法改动。

`AppService` 独占页面状态、活动 runId、封存摘要及结算状态，所有存储事务串行。START/PAUSE/RESUME 在没有排队事务时同步更新只读视图，保留既有同调用栈输入隔离；其返回仍为 Promise。初始化与存档不可用不阻止开始游玩，结算与交易必须取得存储成功结果。失败不会发布钱包/高分/皮肤的部分成功。摘要第一次封存后拒绝替换；旧局身份不能结束新局。同一成功 commandId 重放返回原结果，携带不同内容重用 ID 被拒绝；失败可显式重试。

`SaveRepository` 使用单键 `paoku_save_v1`，schemaVersion=1，revision，walletCoins，highScore，ownedSkinIds，selectedSkinId，audio 五项，settledRunIds。旧九键逐字段迁移、保留原件；新记录成功写入即完成迁移。损坏新记录和未知未来版本明确拒绝读取/覆盖，不重导旧余额；显示默认值只是受保护的不可写视图，不代表恢复了损坏记录中的余额。整数必须非负安全整数；音量有限且在范围内，旧音量越界钳制、损坏值恢复默认。

同源合作标签页通过 Web Locks `paoku-save-transaction-v1` 串行写入，随后以完整 raw token 比较拒绝 stale revision，首个冲突返回 CONFLICT。下一次用户显式重试才重新 load，再执行；结算保留内存摘要，load 后先检查持久幂等记录。初始化迁移中断也可在同一服务、同一活动局内重试，不要求刷新丢失摘要。无 Web Locks 的环境返回 LOCK_UNAVAILABLE，不声称单键 setItem 等于并发事务。直接绕过协议写相同键的旧/外部脚本不在合作锁保证内。

写入抛错时精确读回与目标 encoded 内容相等，才认定写入已经完成；否则保留原内存及失败结果。所有结算 runId 永久保留、不压缩；容量耗尽会显式 SAVE_FAILED，不能通过清除旧 ID 重复发钱。异常关闭尚未结算的局内进度恢复不在范围内；成功结算的 ID、余额和权利可刷新恢复。

商店仅 SHOP 可交易，校验旧五色商品、余额及所有权，BUY 已拥有幂等不扣款，EQUIP 未拥有拒绝。音频只是五项偏好事务，未改声音实现。
