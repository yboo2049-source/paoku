## 2. 产品假设与路线取舍

推荐桌面键盘与手机竖屏同时设计、分档验收。另一方案是先冻结桌面再扩展手机，成本较低但后续 UI/资源返工较多；全面覆盖低端手机可扩大覆盖，但没有目标机和性能数据，暂不承诺。选用双布局和候选预算，可以让 PAO-10、15、16、19 开始估算，设备签收仍由主聊天统一决定。

假设用户为休闲玩家，利用 2–5 分钟碎片时间反复挑战；无尽模式无强制结束时刻。建议新手首局有效游玩中位数 60–120 秒、熟练玩家单局 2–4 分钟，超过 4 分钟仍可继续。以上不是现有留存数据或必须让玩家死亡的设计。

| 局内阶段 | 候选节奏 | 验证方式 |
| -- | -- | -- |
| 0–15 秒 | 先识别三车道和金币，每次只引入一种动作 | 新手无需讲解能理解首次换道/跳跃；记录首次操作和失败原因 |
| 15–45 秒 | 单障碍后才组合动作，逐步出现滑铲与坡面 | 至少 5 名未玩过样板者首次游玩，记录误解和输入失败 |
| 45–90 秒 | 车顶路线、迎面列车、代表道具；紧张段后安排喘息 | 60–90 秒固定样板覆盖路线；与正式无尽单局时长分开 |
| 90 秒以后 | 增加路线选择与组合，保留读路时间和喘息段 | 多种种子与不同速度可达性验证；不得仅提高速度造成骤难 |
| 失败与重开 | 失败原因可理解；重开只需一次明确操作 | 结算稳定后操作可用≤1秒；点击重开到可控≤1秒，均为候选值 |

危险物从无遮挡可辨认到最迟操作点，建议新手≥1.5秒、熟练段≥1.0秒；按相对速度计算距离，迎面列车不能只看玩家速度。组合动作需加上动作占用时间和切道时间。数值留待 PAO-13/23 以路线验证和真人试玩校准。旧速度 18→45、0.25/s、108秒封顶只作迁移基线，不等同新版节奏或 km/h。

## 4. 候选预算及计算口径

下表每列继承 §3 的设备、分辨率和画质；同一预算必须在该档四类场景均测。MiB=2²⁰字节。Q2/Q1/Q0 为未来档位，当前没有切换实现。所有数字均为提案上限，尚未冻结为发布门禁。

| 指标 | D0 / Q2 | M1、I1 / Q1 | M0 / Q0 | 测量与判定方法 |
| -- | -- | -- | -- | -- |
| 帧间隔 | 60fps候选；p95≤18ms，p99≤33.3ms | 60fps候选；p95≤20ms，p99≤33.3ms；不达标评审30fps档 | 30fps候选；p95≤36ms，p99≤50ms | 实际scene渲染提交间隔p50/95/99，>50ms比例≤1%；另报rAF间隔、渲染次数与trace呈现掉帧；16.67/33.33ms是理论周期，单列超周期比例；30fps档不能用仍为60Hz的rAF冒充渲染帧率 |
| 主线程更新/渲染CPU | p95≤8ms | p95≤10ms | p95≤20ms | Performance trace分离模拟、提交渲染、DOM；不与GPU时间简单相加 |
| GPU帧耗时 | p95≤10ms | p95≤12ms | p95≤25ms | GPU timer有效样本，丢弃disjoint；不可用填未测，rAF不能代替GPU耗时 |
| 冷首屏可操作 | ≤3秒 | ≤5秒 | ≤8秒 | 统一下载10Mbps、上传2Mbps、RTT100ms；新profile清缓存/SW；navigationStart→资源就绪且开始按钮可用；每档5次取中位数/p95 |
| 暖首屏可操作 | ≤1.5秒 | ≤2秒 | ≤3秒 | 同profile缓存/SW稳定后刷新5次；与冷启动分报 |
| 首局必要传输量 | ≤8MiB | ≤6MiB | ≤4MiB | production build实测压缩传输字节，包含首局所需模型/贴图/音频/JS；可选内容延后；不能用源码/未压缩包体替代 |
| 首屏阻塞传输量 | ≤2MiB | ≤3MiB | ≤4MiB | 与首局总资源分开；以上限10Mbps计算纯下载约1.68/2.52/3.36秒，其余时延留给RTT、解析和GPU初始化；资源必须在预算内真正可操作，未下载的路线资源不得造成开局卡死 |
| JS堆稳定占用 | ≤200MiB | ≤128MiB | ≤96MiB | DevTools/CDP同GC口径稳态窗口；覆盖后述长跑与重开；不可当成进程总内存 |

| 重开/长跑增长 | 重开后堆增长≤10MiB；长跑末段≤10%且斜率≤1MiB/分 | 同D0 | 同D0 | 同场景预热2分钟，20次重开；长跑15分钟以第2–4与12–15分钟窗口比较；GC前后分开，持续单调增长需调查，不以单点证明泄漏 |
| 可见三角形 | ≤250k | ≤150k | ≤80k | 最密集帧主pass实际提交数量，含实例倍数；另报阴影/特效pass，不用模型源文件三角数代替 |
| draw calls | ≤150 | ≤100 | ≤60 | 引擎帧统计，含阴影和后处理总提交；按pass记录，峰值不得被均值掩盖 |
| 常驻贴图估算 | ≤128MiB | ≤64MiB | ≤32MiB | 枚举常驻尺寸/格式/mip/数组层级并求和；RGBA8含完整mip近似w×h×4×4/3；压缩格式按实际块计算；RT另算 |
| 渲染目标/深度估算 | ≤64MiB | ≤32MiB | ≤16MiB | 按实际内部尺寸、格式、MSAA采样、颜色/深度附件和后处理中间RT累加；不能只按canvas算 |
| 单贴图边长 | 常规≤2048 | 常规≤1024，主角经评审可2048 | ≤1024 | 资产清单与运行常驻检查；例外仍受总贴图预算限制 |
| 活跃粒子 | ≤400 | ≤200 | ≤80 | 所有并发系统活粒子求和，另记录发射器上限8/5/3；峰值道具碎裂与速度线同时采样 |

加载预算须联立：就绪时间至少包含关键路径传输位数/吞吐、依赖往返及解析初始化；不得把8MiB全部放进3秒首屏。首局剩余资源可在菜单和简单开场期间预取，是否够用须用实际依赖时间线验证，不能靠隐藏加载等待通过门禁。

可见几何、贴图、粒子预算用作制作分配：主角/追捕20%，关键列车/障碍/道具40%，环境30%，余量10%；材质与贴图共享后按唯一资源计内存。PAO-7/15/16可提出再分配，但不能分别花完同一总预算。预算超限与帧时间超限均需审查，资产数量达标不意味着帧时间达标。

## 5. 测量协议与结果边界

正式性能签收使用 production build + preview，独立端口5178；冷/暖缓存、PWA/SW及压缩网络条件明确记录。关闭录像和Inspector再测帧时间，截图放测量区间外；固定种子、实体分布、速度、输入序列和相机，跨版本复用。无可用传感器的指标记未测，不为填表估造数值。

| 场景 | 正式验收协议 | 必存证据 |
| -- | -- | -- |
| L 首屏 | 新profile5次冷启动、同profile5次暖刷新；指定网络、无CPU模拟限速 | 导航/资源时间线、压缩字节、就绪定义、失败请求、稳定菜单截图 |
| D 密集段 | 固定样板最大同时实体/粒子/道具组合；预热10秒后采60秒，重复3次 | fixture/种子与实体数量，帧分位数、CPU/GPU trace，几何/贴图/粒子峰值，截图 |
| R 重开 | 预热2分钟后20次正常失败→结算→重开，不用整页刷新代替；相同路段 | 每轮延迟和GC前后堆、节点/材质/纹理数量、结算唯一性、console |
| S 长跑 | 固定路线/种子15分钟，真实输入保活优先；不得把暂停页当长跑 | 分钟序列堆/资源数、帧时间、温度与掉帧趋势、结尾截图 |

QA注入夹具或免死仅用于可重复压力场景，必须标F并与自然输入N分报；它们不证明正常路线可达性、碰撞公平性或真实玩家存活时长。开发服务/单次采样/短时长只能验证工具与暴露风险，不能替代上述签收协议。rAF是页面回调间隔，受调度与显示节奏影响；记录样本数、持续时间、前后台与测量扰动。JS堆不是总RAM，资源尺寸估算不是实测显存。

本次有限采集结果与证据将在 §7 登记。其目的为建立可重复测量基线，正式真机、压缩部署和15分钟热稳定验收属于 PAO-25；不以候选规格完成冒充全部性能验收。

## 6. 超预算处理及回升规则（待实施）

按成本从低到高降级：先减少非交互装饰/远景和并发粒子，再关额外辉光/景深等后处理，降阴影分辨率及投影体范围，然后降低内部渲染比例与贴图LOD；仍不满足时才经评审选30fps档。危险轮廓、金币路径、道具语义、脚底支撑、碰撞与模拟tick不得随画质改变。

候选自动策略：连续三个5秒窗口p95超档位阈值则降一档，至少30秒冷却；性能连续60秒留有20%余量且无热降频再允许回升，用户手动锁档优先。正式冷启动超限先延后可选内容、压缩和缓存首局资源；长跑内存增长先排查生命周期/池上限和资源释放，不能靠画质降低掩盖泄漏。指标恢复后重新跑四场景与视觉检查；关闭后处理仍需保持明亮城市风格和读路能力。
