# PAO-15 角色绑定与动作交付准备设计

2026-11-01（Asia/Shanghai）｜v0.1｜brainstorming：Bounded资产专项设计，涉及下游接口但不改架构。**待评审；仅准备交付，不是正式制作或PAO-18启动许可。**

## 1. 目标与有效输入

以现有原创runner为优先形象，提出可制作、可导入、可检验的正式骨骼与13动作方案，补齐源文件、权利、拓扑/蒙皮和工具缺口。详细契约见[character-spec](../../art/character-spec.md)，可核实事实与输入版本见[PAO-15证据](../../evidence/PAO-15/README.md)。本次采用using-superpowers的方法论基线与brainstorming的上下文/备选/设计审查流程；用户已指定交具体方案，待决项集中为制作前门禁，不在写准备文档前重复索取总体批准。

总体已批准：明亮城市轨道、整体逐段替换、先完整样板、原地动作由模拟驱动。PAO-7/8具体风格/设备预算仍候选；PAO-9修订技术契约可沿既有M1接受范围使用，不把它仍In Review曲解为M1需重批，也不扩大为角色制作放行。Linear PAO-15 blockedBy=7/8/9、blocks=18，当前Backlog；本次不改状态或发布评论。

## 2. 三条制作路径与推荐

| 路径 | 前提与结果 | 风险 / 决策 |
| --- | --- | --- |
| A 原GLB Agent补源、权利和制作条件，再在副本规范化/蒙皮/原创动作 | 保持现有runner造型；由原作者解释34部件、恢复DCC工程、低模和分层贴图；先检查可绑定性再估工 | 推荐。最少造型返工；源和许可尚未取得，不能承诺直接可绑或已派单 |
| B 缺源但授权明确时，由经批准制作方从GLB导入重建可编辑工程并修拓扑、重烘焙、绑定和原创动作 | 必须获修改/衍生/发布授权，先证明GLB足够恢复；保留原文件、输出新版本 | 返工量可能大，导入GLB无法恢复原控制器/分层贴图；需新估价/设计批准，不能自动降级采用 |
| C 原资产不可用时另委托原创可动画样板 | 新造型/源/许可/全套动作/LOD完整交付，再做同屏审查 | 成本与造型变动最大；仅列备选，须明确替换授权，本轮不重做原作者资产 |

直接套旧player动作不列为可用捷径：新runner无skin、旧67关节与候选≤48不一致、7动作也不完整。未来若另提重定向，需动作来源许可、rest pose/骨长/轴映射、重采样和人工修姿势专项审核，仍缺本任务其他动作；本方案优先原创动作，不借此扩大授权。

## 3. 具体交付设计与数据流

角色采用脚底中心单一root，m/Y-up/+Z前，候选1.8m。23具名节点基础树可扩到≤48关节，每顶点≤4权重；rest pose、逆绑定矩阵、蒙皮和LOD共享骨架版本，工具控制骨不导出。作者源中完成模型/骨架局部动作，30fps输出13clip；所有clip root XYZ无位移，pelvis保留重心与肢体动作。待机、跑、跳三段、滑三段、左右换道、受击、失败、板姿态逐项给帧区间/标记/循环/中断，避免“有run就算全套”。

源→副本检查→权利与拓扑审查→规范化和蒙皮→完整动作/挂点→GLB/贴图/manifest→真实Babylon导入预览→PAO-15独立验收→固定提交交Dispatcher→PAO-18消费。此为门禁后制作路径，不是当前执行计划。模拟只读事实→PAO-18姿态选择/混合→骨架/附件；动画标记只触发表现。不能通过clip回调移动角色、落地、扣盾或结算；暂停按模拟冻结，重开清理旧runId。

文件级接口为统一skeletonId、clip名称/采样表、挂点parent/TRS、资产空间矩阵/一次转换记录、资源/hash/许可manifest。候选输出目录、字段和容差见规格§6–7，当前不创建实现目录或TS类型。PAO-18需要本任务正式动作和PAO-17可用渲染接口后才能接线；本轮不代其写播放器/镜头。

## 4. 缺口与失败处理

| 缺口 | 当前证据结论 | 解除方式 / 接收责任 |
| --- | --- | --- |
| 原GLB Agent可编辑源 | 限定交付目录未取得；未联系作者，不能宣称已确认有/无源 | Dispatcher向原作者收DCC工程/贴图/版本/hash，PAO-15验证可打开 |
| 角色与贴图许可/AI来源 | 清单generator不证明许可；未取得条款、参考来源、账号/生成时权利证据及贡献归属 | 权利人提供授权原文/制作方法/日期/工具版本/参考/署名/再分发限制；权利审查签收 |
| 绑定/蒙皮可行性 | 无skins/weights交付；仅拆件静态结构，关节区域拓扑未知 | 原作者部件语义表及DCC变形样条；需要修拓扑时先报返工 |
| DCC/导出环境 | node/npm可用；PATH中未发现blender；未探测全部磁盘/其他机器 | 制作方报确切工具/版本、导出器和烘焙流程；缺工具不下载安装或伪造动作 |
| 朝向/最终尺度 | 脚底/场景高已记录；面向仍未标定，1.8m及1.838423倍只是候选 | 同屏样板与轴标记预览签收；重新测蒙皮后高度 |
| 预算/追捕者范围 | 12k/48骨/贴图档为候选；未授权完整NPC动作 | 主审确认适用PAO-7/8条目与一runner样板范围；NPC另列任务/预算 |

缺源/权利时停在缺口表；不把未取得变成程序化颠簸替代。导入/蒙皮/预算失败退回同版源修复；原始GLB保持只读，任何将来制作都在新版本副本。运行时加载失败回退方案由PAO-17/18另外评审；保留旧版可玩只算迁移回退，不算正式runner验收通过。

## 6. 验证计划及本轮完成标准

本轮：核对Git与Linear原生依赖；读取指定固定规格/角色清单，复核runner文件hash；审查13clip覆盖、采样时长、骨架节点数量/父级、原地根策略、挂点和预算口径；审查引用与白名单；git diff --check；正常hooks提交并首次push -u origin HEAD，再核对远端SHA。无代码改动，不为纯文档新跑E2E或浏览器，不沿用历史截图冒充本轮验证。

正式制作：先有CA-01源/许可，再制作骨架/权重试样证明CA-02；变形、朝向、根轨道、循环边界、挂点、预算和真实导入逐项检验；任何失败保留日志/版本并返工。正式接线才由PAO-18先铺失败测试：缺clip/错骨架拒绝、根重复位移、暂停相位、重开旧标记、空中滑铲、真实落地、同tick终局优先、板到期与反向换道；再实现，通过build/test/完整E2E和自然输入录屏。桌面/竖屏真实截图检查人物及附件无遮挡，真机品质和帧时间仍由对应性能/集成任务签收。
