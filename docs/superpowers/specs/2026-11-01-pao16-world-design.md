完整规格见 [world-assets.md](../../art/world-assets.md)，可复核输入见 [证据索引](../../evidence/PAO-16/README.md)。依用户指示一次交完整待审设计，不在每小节要求反复确认。使用using-superpowers/brainstorming的上下文→备选→设计→验证思路；原`~/.workbuddy/skills/`路径缺失，在插件缓存找到同名技能，来源记录在证据内。项目本地方法论门禁与用户指定写权优先于技能默认的docs/plans路径。

## 2. 三种方案与推荐

| 方案 | 收益 | 代价 / 结论 |
| --- | --- | --- |
| A：复用已交付GLB，权威逻辑目标约束源标记标定，批准后制作派生LOD/贴图 | 保留作者方向与溯源；一次转换和单组合根易审查，允许逐件回退 | 可编辑源/许可、端点/净空和比例尚缺，不能保证一矩阵解决；推荐 |
| B：仅等比缩放直接接入原全量资产 | 原文件不动，准备成本低 | 车/坡比例与逻辑不必匹配，4K/高面资产不满足候选低档；只适合门禁后的有限技术探针，不作为生产交付 |
| C：重新制作整批模型或修改物理迎合外观 | 可以自由统一尺寸 | 越出用户授权、丢原作者方向、破坏M1权威；本次排除 |

## 3. 推荐设计与数据流

固定源提交/SHA → 只读manifest选8件主样本 → 将既有S解析、H哈希、V两张技术预览与C/U分开 → 标记scene点 → 候选N及资产到逻辑重基 → 对照现有Surface/逻辑目标 → 门禁后派生优化与正式验收。当前停在设计和缺口阶段，源点/矩阵/误差保持null。

场景样板是一段160m技术容器；选门架/洞口、普通列车、带坡工程车、高低栏、金币、MAGNET代表道具。主题轨道/站台源缺、普通车完整端面未验，明确不能称完整可玩主题交付。普通车静止/迎面复用同源，速度只来自模拟。新喷气包/护罩/宝箱不授予玩法。

保留`carriage→train_ramp_or_car`与`ramp-truck→train_metro`；工程车一组RAMP+ROOF逻辑孩子共一个视觉根，自带坡不另画。本树坡深6、车深12、共同点(0,3,73)，与M0的12m坡/18m车算例分别验证。源TRS先进入scene，N不重复节点X+90°，loader手性只转换一次；逻辑代理已在L空间，不再套美术重基。

拟议JSON结构、单位/原点、组合矩阵、源标记、代理、LOD、资源ID、状态/回退字段见规格§3–6。准备证据中的JSON仅是取证摘要，不是运行时配置，也不提前创建`docs/assets/pao16-calibration.json`。

## 4. 失败与优化边界

哈希/许可/源缺、无法同时对齐坡脚/坡顶/车顶、门架柱脚侵入合法路线、低档剪影不清或资源失败，整件/组合保持UNCALIBRATED并回退LEGACY_PRIMITIVES；不改逻辑尺寸、Surface容差、跳跃或拾取范围。旧表现坡体遮挡等仍是遗留项，准备稿不声称修复。

采用M0同一套候选分配：车6000/3000/1200面、障碍800/400/160、币道具400/200/80等，保护通行边缘；世界纹理稳态72/36/15MiB，与角色/UI/FX合计及串行过渡峰值统一核算。具体设备/美术尚待适用项确认，无法将源文件统计或预算算式标为GPU性能通过。
