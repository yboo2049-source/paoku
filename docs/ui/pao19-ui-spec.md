# PAO-19 DOM UI 规格提案

版本：v0.1，2026-11-01（Asia/Shanghai）。状态：准备阶段送审，未批准、未实现、未做浏览器验收。

## 1. 范围与依据

沿用已批准的明亮风格化城市轨道与 PAO-14 应用权威。只设计开始、局内 HUD、暂停、结算及必要的商店/音频兼容入口，不新增玩法、钱包、存档、结算或音频事务。PAO-19 当前 Backlog，原生 blockedBy 为 PAO-7（In Review）与 PAO-14（Done）。准备交付不释放 PAO-7 门禁，不把父任务标完成。

依据：本树 [PRD](../PRODUCT_REQUIREMENT_DOCUMENT.md) 的新方向补充、[架构](../ARCHITECTURE_DESIGN.md) 的米制/深只读约束、[总设计 §8–9](../superpowers/specs/2026-10-31-paoku-complete-rebuild-design.md)、[PAO-14 UI 审查](../evidence/PAO-14/ui-integration-review.md)。旧霓虹/赛博文案为待替换内容，旧测试文档中的 DOM 存档描述为历史事实，不作为当前接口。外树只读来源与 Git 基线见 [准备证据](../evidence/PAO-19/README.md)。

## 2. 候选设计系统

下列数值均待批准及实际 DOM 验证。采用 PAO-7 v0.2 的浅色实体卡片，深色文字；语义色仅点缀，不把浅金或薄荷用作浅底小字。无外部字体依赖；字体栈候选为 system-ui、Segoe UI、Microsoft YaHei、sans-serif。数字用 tabular-nums，不用固定高度截断中文。

文字对比验收目标：普通文字至少4.5:1，大字至少3:1；控件边界/焦点至少3:1。这里是目标而非已测结果；不合格先调整配对或增加实体底，不私改世界色板。

按钮四态：常态深底浅字；hover 加浅色外框与轻微明度变化；pressed 内描边及1px位移；disabled 浅底深灰字、禁用属性和原因文案，不能只降透明度。secondary 常态浅底深字、边框2px；同样覆盖四态。focus-visible 另加3px深色轮廓、2px浅色隔离，不替代四态。触屏无 hover 也有按下反馈。所有点击目标至少48×48 CSS px，按钮间距至少8px；音量滑杆点击区域也至少48px高。按钮不使用会让命中框变小的缩放。

## 3. 页面布局与安全区

布局切换候选断点768 CSS px：以上使用桌面布局，以下使用竖屏紧凑布局，短横屏另允许卡片滚动。根区域以可见动态视口为边界，优先100dvh、保留100vh回退；四边留白为基础边距加对应 env(safe-area-inset-*)。现有 index.html 未声明 viewport-fit=cover，真实刘海覆盖需最小请求 I-02，未批准前不能宣称全屏安全区通过。

| 页面 | 桌面 | 390×844 竖屏 |
|---|---|---|
| 开始 | 左侧卡片宽400px、距左24px、垂直居中；角色及中央路线留在右侧可见区；标题“城市跑酷”、最高分/钱包、“开始奔跑”、次级商店与音频设置、键盘说明 | 底部卡片宽358px（无安全区时）、左右16px、距底16px；最大高约可用高度55%，独立内部滚动；上方保留人物预览；开始按钮全宽，商店次级；说明改为左右滑换道、上滑跳、下滑翻滚 |
| HUD | 顶部左侧成绩/本局金币，右侧声音与暂停；速度在成绩下方；道具靠左侧，单条宽≤200px | 顶行可用宽358px：成绩/金币区246px，间距8px，声音48px、间距8px、暂停48px；数字过长时区内换行增高；速度另起一行；道具底部两列，每列175px、间距8px，四道具最多两行 |
| 暂停 | 居中卡片宽400px，继续→重开→返回菜单；说明“重开或返回将结束本局并尝试保存” | 宽358px，按钮全宽纵排；受可用高度限制时滚动；继续优先，顶部标题可见 |
| 结算 | 居中卡片宽440px；结果→分数→拾取/任务奖励/总收益→保存状态→重开/商店/返回 | 宽358px；成绩突出，收益分行；同一按钮顺序；长错误/放大字体在卡片内部滚动，不压到屏幕外 |

HUD 中央候选保留区：横向25%–75%、纵向25%–88%，不放常驻不透明卡片；人物、追捕者与前方路线以实际镜头截图复核，不能用百分比保证所有动作。竖屏道具条在底部保留区外，两个48px高行加8px间隔；如碰到人物或安全区，改靠边紧凑列，须重新审截图。大字号/超长数值时优先完整显示分数/币数及暂停，隐藏装饰速度进度条、缩短辅助说明；不裁数字、不用省略号冒充真实金额。中央保留区与必要可读内容冲突时记录布局失败，不能静默遮盖路线。

层级候选：canvas=1、HUD=10、普通Toast=20、modal遮罩=30、modal内容/其错误条=31。HUD空白区 pointer-events:none；按钮可接收输入。暂停/结算遮罩拦截点击、触摸、滚轮，焦点限制在活动弹窗；隐藏页面 inert/不可聚焦，Escape只走现有桥。Tab顺序按视觉顺序，弹窗打开聚焦主操作，继续后恢复暂停按钮焦点；重开后清旧页面焦点。UI点击/滑杆/滚动不可同时产生游戏动作；输入层若未过滤控件，仅提跨层请求，不自行改模拟。低动态模式优先 follows prefers-reduced-motion，不新增持久化设置；取消位移与非必要进入动画，不闪烁催促。

## 4. 数据展示与道具

| 展示项 | 唯一来源 | 规则 |
|---|---|---|
| 页面、钱包、高分、外观权益、音频设置 | AppSnapshot | 单次 update 捕获同一份 readApp()；不拼 DOM 文本生成下一状态 |
| 局内分/币/速度/道具剩余秒数 | update 的 DeepReadonly<GameContext> | 仅投影；score向下取整；局内金币标“本局金币”，不同于钱包 |
| 结算 | AppSnapshot.summary / settlementStatus | summary为空显示“等待结算数据”，不用旧ctx补算收益；COLLISION只写“碰撞结束”，QUIT写“主动结束”，不猜障碍类型 |
| 新纪录 | markNewRecord(runId) 与 summary.runId | 匹配才显示，不用UI重新判定历史纪录 |

速度推荐保留 m/s，一位小数，例如18→“18.0 m/s”。如批准切换km/h，必须先乘3.6：18→64.8 km/h、45→162.0 km/h；不得将floor(ctx.speed)直接标KM/H。速度进度用现有上下限计算并限制0–100%，不改加速规则。

| 枚举 | 中文名 / 图标语义 | 倒计时规则 |
|---|---|---|
| MAGNET | 磁铁 / U形磁铁 | 只读Map中剩余秒数，正值向上取整为整数秒 |
| DOUBLE_SCORE | 双倍得分 / 菱牌×2 | 同上；不在UI计算积分倍率 |
| SUPER_SNEAKERS | 超级跑鞋 / 成对鞋 | 同上；不改变跳跃 |
| HOVERBOARD | 悬浮滑板 / 长板 | 同时核对hoverboardActive；有可信正计时才显示秒数；仅active且无计时则显示“保护中”，不编造持续时间 |

图标候选为现有/新内联SVG，20–24px，图形不引用3D资源或emoji字体；装饰图标aria-hidden，名称/时间有可读文本。固定以上顺序、按类型更新同一节点；0秒消失，暂停时不自行减时。异常负值/非有限值不展示虚构秒数，显示“时间不可用”或无效项隐藏并记录测试；未知枚举不暴露内部字符串，显示“道具”。四种图标与中文名不因资源新增jetpack/shield/mystery_box而扩展玩法。

## 5. Toast、等待、错误与重试

Toast是表现队列：最多1条可见＋3条等待（总容量4），普通消息FIFO；同一runId和文本在2秒内重复只更新一条；满时丢最老等待普通消息，绝不无限堆DOM。每条显示3秒、淡出≤160ms，离开页面/换run时清理旧局普通队列与定时器；页面隐藏暂停展示计时，恢复后继续。输入文本走textContent，不插HTML；空串忽略，过长消息折为两行摘要，完整文字在可访问名称中保留。普通通知不抢焦点，aria-live=polite；不重复按帧播报。旧showToast(message:string)入口保留，无法可靠判断类别的旧字符串按普通通知处理，禁止解析“ACTION FAILED”反推业务结果。

普通Toast：桌面靠上方左侧HUD下缘，竖屏位于道具区上方且避开中央路线；位置冲突时延后播放。modal打开时不把普通消息盖在按钮上。交易/结算错误固定在活动卡片错误条，错误只播报一次；它不被普通队列挤掉，用户操作成功或明确关闭后才清除。任务完成消息只解释“本局奖励”，不把MISSION_COMPLETED当发币或已入钱包凭证。现有任务提示音调用保持原职责与次数，不在新队列出队时再播放。

| 状况 | 文案/操作 | 数据与时序约束 |
|---|---|---|
| settlementStatus=PENDING | “正在保存本局…”；阻止重复结束操作 | 不提前显示已入账或清世界 |
| COMMITTED | “本局已保存” | 钱包仍直接取AppSnapshot，不加earnedCoins |
| FAILED / SAVE_FAILED / STORAGE_UNAVAILABLE / LOCK_UNAVAILABLE | “保存未完成，请重试原操作”；保留摘要/现场 | 沿用重开/返回/商店原意图显式重试，无自动轮询或新结算命令 |
| CONFLICT | “数据已变化，请确认后重试” | 用新快照刷新，不合并钱包 |
| STALE_RUN / INVALID_STATE | “本局状态已变化，请重新选择操作” | 取消旧局视觉等待，不能把旧命令重绑新局 |
| INSUFFICIENT_FUNDS / NOT_OWNED / UNKNOWN_SKIN | 余额不足 / 尚未拥有 / 外观不可用 | 不乐观发币、装备或解锁 |
| FUTURE_SCHEMA / CORRUPT_SAVE | 说明存档版本不兼容 / 数据异常 | 不提供UI自行清档按钮，不承诺已修复 |
| 其余错误（包括INVALID_AUDIO） | “操作未完成，请重试”＋可读原因 | 失败音频偏好仍展示提交快照；显式重新提交UPDATE_AUDIO字段意图 |

一般命令的精确pending/结果当前无结构化UI回执，不能仅靠300ms节流或snapshot.errorCode可靠关联。请求 I-01（见任务设计）获批后：点击即锁同组互斥操作、300ms仍pending显示“正在处理…”，5秒后改“仍在处理，请稍候”，不超时判失败、不自动重发；结果按commandId/runId清等待，成功再按快照展示，失败恢复原按钮供显式重试。没有I-01时只能准确展示settlementStatus的等待和现有showToast通用失败提示，不得宣称一般命令等待/错误条已完整达标。

## 7. 批准项与交接

待批准仅为本稿任务细节：浅色卡片token/字号/四态与SVG语义；桌面左卡/竖屏底卡和HUD保留区；m/s显示；Toast容量/去重/时长；保存与一般命令反馈；I-01/I-02最小跨界请求。总体路线及M1不重审。批准结果须记录版本、批准项、修改意见及批准人/时间。

共享文档建议交Dispatcher：PRD链接四页与失败反馈验收；架构补UI只读投影与命令反馈边界；TEST_PLAN登记R01–R09和N/F布局矩阵；SYSTEM_WORKFLOW记录等待/重试不改变事务；PROGRESS仅标“设计已审/白名单待解锁”。本轮不修改这些文件。批准后先同步共享文档并明确白名单，再writing-plans、RED、实现；不得凭本规格自动启动后续任务。
